# Project Hub — เว็บไซต์ศูนย์รวมโปรเจกต์และกิจกรรมของค่าย

เว็บไซต์สำเร็จรูปสำหรับค่าย/ทีมสร้างสรรค์ ใช้แนะนำโปรเจกต์ ประชาสัมพันธ์กิจกรรม และเผยแพร่ข่าวสาร
พร้อม **ระบบจัดการหลังบ้าน (Admin Panel)** ที่ใช้จัดการเนื้อหาได้เองทั้งหมดโดยไม่ต้องแก้โค้ด

สร้างด้วย **Node.js + Express + EJS + MySQL/MariaDB** ทำงานแบบ Server-Side Rendering
จึงแสดงผลได้ครบถ้วนแม้ปิด JavaScript และเหมาะกับการทำ SEO

## 1. ฟีเจอร์ทั้งหมด

### 1.1 หน้าเว็บไซต์สาธารณะ

| หน้า | เส้นทาง | รายละเอียด |
| --- | --- | --- |
| หน้าแรก | `/` | ส่วนแนะนำ (Hero) / สถิติ / โปรเจกต์เด่น / โปรเจกต์ทั้งหมด / กิจกรรมกำลังจะเปิดตัว / ข่าวล่าสุด / ช่องทางติดต่อ |
| โปรเจกต์ทั้งหมด | `/projects` | ค้นหา + กรองตามประเภทและสถานะ + เรียงลำดับ + แบ่งหน้า |
| รายละเอียดโปรเจกต์ | `/projects/:slug` | เนื้อหาเต็ม จุดเด่น แกลเลอรี วิดีโอ กิจกรรมที่เกี่ยวข้อง และข้อมูลสรุปด้านข้าง |
| กิจกรรม | `/events` | แท็บ กำลังจะเปิดตัว / กำลังดำเนินอยู่ / ที่ผ่านมา พร้อมตัวกรองและช่วงเวลา |
| รายละเอียดกิจกรรม | `/events/:slug` | วันเวลา สถานที่ ข้อกำหนดการเข้าร่วม ลิงก์เข้าร่วม แกลเลอรี วิดีโอ และโปรเจกต์ที่เกี่ยวข้อง |
| ข่าวสาร | `/news` | ค้นหา + กรองตามหมวด + แบ่งหน้า |
| รายละเอียดข่าว | `/news/:slug` | เนื้อหาข่าว รูปประกอบ วิดีโอ และเวลาเผยแพร่ |
| เกี่ยวกับเรา | `/about` | เรื่องราวของค่าย พันธกิจ ช่องทางติดต่อ |
| Sitemap / Robots | `/sitemap.xml` · `/robots.txt` | สร้างอัตโนมัติจากข้อมูลจริงในฐานข้อมูล และกันไม่ให้จัดทำดัชนีหน้าหลังบ้าน |
| หน้า 404 / 500 / 403 | — | หน้าแสดงข้อผิดพลาดที่ออกแบบให้เข้ากับธีมเว็บไซต์ |

**จุดเด่นของฝั่งเว็บไซต์**: รองรับภาษาไทยเต็มรูปแบบ รูปภาพ lazy-load เปิดดูวิดีโอแบบไม่โหลดสคริปต์ภายนอกจนกว่าจะกดเล่น
มีโครงสร้าง SEO (meta description, Open Graph, canonical, sitemap) และออกแบบให้ใช้ได้ทั้งบนมือถือ แท็บเล็ต และคอมพิวเตอร์

### 1.2 ระบบหลังบ้าน (Admin)

- **แดชบอร์ด** — สรุปจำนวนโปรเจกต์/กิจกรรม/ข่าว/ไฟล์สื่อ, สถานะระบบ (ฐานข้อมูล ตาราง ผู้ดูแล โฟลเดอร์อัปโหลด), รายการแก้ไขล่าสุด และทางลัด
- **จัดการโปรเจกต์** — เพิ่ม/แก้ไข/ลบ เผยแพร่หรือเก็บเป็นฉบับร่าง ตั้งเป็นโปรเจกต์เด่น จัดลำดับการแสดงผล
- **จัดการกิจกรรม** — กำหนดวันเวลา สถานที่ ข้อกำหนด และ **ตั้งเวลาเผยแพร่อัตโนมัติ** พร้อมการคำนวณสถานะอัตโนมัติ (กำลังจะเปิดตัว / กำลังดำเนินอยู่ / สิ้นสุด) และการล็อกสถานะที่กำหนดเอง
- **จัดการข่าวสาร** — เขียนข่าว บันทึกฉบับร่าง หรือเผยแพร่ทันที กำหนดเวลาเผยแพร่ได้
- **คลังไฟล์สื่อ** — อัปโหลดรูปภาพ/วิดีโอ (ลากไฟล์มาวางได้) ตรวจชนิดไฟล์จากเนื้อหาไฟล์จริง ตั้งชื่อไฟล์ใหม่ให้ปลอดภัย นำไฟล์เดิมกลับมาใช้ซ้ำ และลบไฟล์ที่ไม่ได้ใช้งาน
- **ตัวจัดการไฟล์ของแต่ละเนื้อหา** — รูปปก แกลเลอรีรูปภาพ (แก้คำบรรยาย/จัดลำดับ/ลบ) และวิดีโอ (YouTube, Vimeo หรือไฟล์อัปโหลด)
- **ตั้งค่าเว็บไซต์** — ชื่อแบรนด์ โลโก้ Favicon สี Accent ข้อความทุกส่วนของหน้าแรก ข้อมูลหน้าเกี่ยวกับเรา ช่องทางติดต่อ SEO และส่วนท้ายเว็บไซต์
- **บัญชีผู้ดูแล** — เปลี่ยนรหัสผ่าน และดูประวัติการจัดการ (Audit Log) ว่าใครแก้ไขอะไร เมื่อใด จากไอพีใด

## 2. โครงสร้างโปรเจกต์

```
project-hub/
├── backend/                     # ส่วนเซิร์ฟเวอร์ (Node.js + Express)
│   ├── config/                  # การโหลดค่า .env, การเชื่อมต่อฐานข้อมูล, ค่าคงที่ภาษาไทย
│   ├── controllers/             # ตัวควบคุมหน้าเว็บสาธารณะ และตัวควบคุม REST API
│   ├── middleware/              # ตรวจสอบข้อมูลนำเข้า, CSRF, สิทธิ์ผู้ดูแล, อัปโหลดไฟล์, จัดการข้อผิดพลาด
│   ├── routes/                  # เส้นทางของหน้าเว็บ (public.js) และของ API (api.js)
│   ├── scripts/                 # สคริปต์ migrate / seed / create-admin / check-system
│   ├── services/                # ตรรกะทางธุรกิจ (โปรเจกต์, กิจกรรม, ข่าว, ไฟล์สื่อ, ตั้งค่า, บัญชี, Audit Log)
│   ├── utils/                   # ตัวช่วยเหลือ (slug ภาษาไทย, ลิงก์วิดีโอ, สถานะ, view helpers)
│   ├── uploads/                 # ไฟล์ที่อัปโหลด (แยกโฟลเดอร์ projects / events / news / settings)
│   └── server.js                # จุดเริ่มต้นของเซิร์ฟเวอร์
├── database/schema.sql          # สคีมาฐานข้อมูล (11 ตาราง)
├── frontend/                    # ส่วนหน้าเว็บ
│   ├── admin/                   # หน้า HTML ของระบบหลังบ้าน (เรียกข้อมูลผ่าน REST API)
│   ├── partials/                # ส่วนประกอบที่ใช้ซ้ำ (head, nav, footer, การ์ด, แบ่งหน้า)
│   ├── assets/css|js|images/    # ไฟล์สไตล์ สคริปต์ และรูปภาพของเว็บไซต์
│   └── *.ejs                    # เทมเพลตหน้าเว็บสาธารณะ
├── tools/                       # เครื่องมือช่วยพัฒนา (สร้างภาพตัวอย่าง, ทดสอบระบบครบวงจร)
├── .env.example                 # ตัวอย่างค่าตั้งต้น (คัดลอกเป็น .env แล้วแก้ค่า)
└── package.json
```

## 3. สิ่งที่ต้องติดตั้งก่อนเริ่ม

- **Node.js 18 ขึ้นไป** (แนะนำ 20 หรือ 22) และ npm
- **MySQL 8 หรือ MariaDB 10.4 ขึ้นไป**
- (ทางเลือก) **Python 3 + Pillow** หากต้องการสร้างภาพตัวอย่างใหม่ด้วย `tools/generate-seed-images.py`

ตรวจสอบเวอร์ชันด้วยคำสั่ง

```bash
node -v && npm -v
```

## 4. ขั้นตอนติดตั้งและเปิดใช้งาน

### ขั้นที่ 1 — ติดตั้งไลบรารี

```bash
cd project-hub
npm install
```

### ขั้นที่ 2 — สร้างไฟล์ค่าตั้งต้น

```bash
cp .env.example .env      # Windows: copy .env.example .env
```

จากนั้นแก้ค่าใน `.env` อย่างน้อย 3 จุด คือ `DB_USER`, `DB_PASSWORD` และ **`SESSION_SECRET`**
(ควรเป็นข้อความสุ่มยาวอย่างน้อย 32 ตัวอักษร) และแก้ `SITE_URL` ให้ตรงกับที่อยู่จริงของเว็บไซต์

### ขั้นที่ 3 — สร้างฐานข้อมูลและนำเข้าตาราง

```bash
mysql -u root -p -e "CREATE DATABASE project_hub CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
npm run migrate
```

### ขั้นที่ 4 — สร้างบัญชีผู้ดูแลระบบ

```bash
npm run create-admin
# หรือกำหนดเอง: node backend/scripts/create-admin.js --email you@example.com --password "รหัสผ่านของคุณ" --name "ชื่อที่แสดง"
```

รหัสผ่านจะถูกเข้ารหัสด้วย **bcrypt** ก่อนบันทึกลงฐานข้อมูลเสมอ

### ขั้นที่ 5 — เพิ่มข้อมูลตัวอย่าง (ไม่บังคับ แต่แนะนำสำหรับทดลองใช้)

```bash
npm run seed              # เพิ่มข้อมูลที่ยังไม่มี (ไม่ทับข้อมูลเดิม)
npm run seed -- --reset   # ลบข้อมูลตัวอย่างเดิมแล้วเพิ่มใหม่ทั้งหมด
```

### ขั้นที่ 6 — เปิดใช้งาน

```bash
npm start                 # โหมดใช้งานจริง
npm run dev               # โหมดพัฒนา (รีสตาร์ตอัตโนมัติเมื่อแก้โค้ด)
```

จากนั้นเปิดเบราว์เซอร์

| ส่วน | ที่อยู่ |
| --- | --- |
| เว็บไซต์สาธารณะ | http://localhost:3000/ |
| ระบบหลังบ้าน | http://localhost:3000/admin |
| เอกสาร API | http://localhost:3000/api |

บัญชีเริ่มต้นที่ได้จากข้อมูลตัวอย่าง: `admin@nexuscamp.local` / `Admin@12345`
**ควรเปลี่ยนรหัสผ่านทันที** ที่เมนู ตั้งค่าเว็บไซต์ → บัญชีของฉัน

## 6. การใช้งานระบบหลังบ้าน

1. เข้าที่ `/admin` ระบบจะพาไปหน้าเข้าสู่ระบบ
2. เพิ่มเนื้อหาใหม่จากเมนูด้านซ้าย
   - **โปรเจกต์** — กรอกชื่อ คำโปรย รายละเอียด และจุดเด่น (พิมพ์หนึ่งบรรทัดต่อหนึ่งข้อ) แล้วอัปโหลดรูปปกและแกลเลอรี
   - **กิจกรรม** — กำหนดวันเวลาเริ่ม/สิ้นสุด สถานที่ และข้อกำหนด ระบบจะคำนวณสถานะให้อัตโนมัติ (หรือเปิด "ล็อกสถานะ" เพื่อกำหนดเอง)
   - **ข่าวสาร** — เขียนเนื้อหาโดยเว้นบรรทัดว่างเพื่อขึ้นย่อหน้าใหม่
3. กด **บันทึกเป็นฉบับร่าง** เพื่อเก็บไว้ก่อน หรือ **บันทึกและเผยแพร่** เพื่อให้แสดงบนเว็บไซต์ทันที
4. สำหรับกิจกรรม/ข่าว สามารถกำหนด **วันเวลาเผยแพร่ล่วงหน้า** ระบบจะเผยแพร่ให้เองเมื่อถึงกำหนด
5. ไฟล์สื่อทุกไฟล์เก็บใน **คลังไฟล์สื่อ** และนำกลับมาใช้ซ้ำได้จากปุ่ม "เลือกจากคลังสื่อ"

> **หมายเหตุ**: ต้องกดบันทึกข้อมูลครั้งแรกก่อน ระบบจึงจะเปิดให้เพิ่มรูปภาพ/วิดีโอของรายการนั้นได้
> เพราะไฟล์สื่อผูกกับรหัสของเนื้อหา

## 7. โครงสร้างฐานข้อมูล

ฐานข้อมูล `project_hub` ประกอบด้วย 11 ตาราง (สร้างครบด้วย `npm run migrate`)

| ตาราง | หน้าที่ |
| --- | --- |
| `admin_users` | บัญชีผู้ดูแลระบบ (รหัสผ่านเข้ารหัส bcrypt, มีบทบาท admin/editor และการล็อกบัญชี) |
| `sessions` | เก็บ session ของผู้ดูแลในฐานข้อมูล (ไม่ใช้หน่วยความจำของเซิร์ฟเวอร์) |
| `login_attempts` | บันทึกความพยายามเข้าสู่ระบบ เพื่อป้องกันการเดารหัสผ่าน |
| `projects` | ข้อมูลโปรเจกต์ |
| `project_media` | รูปภาพและวิดีโอของโปรเจกต์ |
| `events` | ข้อมูลกิจกรรม (วันเวลา สถานะ สถานะล็อก เวลาเผยแพร่) |
| `event_media` | รูปภาพและวิดีโอของกิจกรรม |
| `news` | ข่าวสารและประกาศ |
| `news_media` | รูปภาพและวิดีโอของข่าว |
| `site_settings` | ค่าตั้งต้นของเว็บไซต์ (แก้ไขได้จากหน้าตั้งค่า) |
| `audit_logs` | ประวัติการจัดการทั้งหมดในระบบหลังบ้าน |

ตารางที่ผูกกับโปรเจกต์ใช้ `FOREIGN KEY ... ON DELETE CASCADE` จึงลบข้อมูลหลักแล้วไฟล์สื่อที่เกี่ยวข้องถูกลบตามไปด้วย

## 9. การทดสอบระบบ

สคริปต์ทดสอบครบวงจรจะตรวจ 59 รายการ ครอบคลุมหน้าเว็บสาธารณะทั้งหมด การเปลี่ยนเส้นทางของผู้ที่ยังไม่เข้าสู่ระบบ
การปฏิเสธคำขอที่ไม่มีโทเคน CSRF การเพิ่ม/แก้ไข/ลบข้อมูลผ่าน API การอัปโหลดไฟล์ (รวมถึงการปฏิเสธไฟล์ที่ไม่ใช่รูปหรือวิดีโอ) และการออกจากระบบ

```bash
npm start                        # เปิดเซิร์ฟเวอร์ไว้ในหน้าต่างหนึ่ง
bash tools/smoke-test.sh         # เปิดอีกหน้าต่างแล้วรัน
bash tools/smoke-test.sh https://your-domain.com   # ทดสอบกับเซิร์ฟเวอร์อื่นได้
```

ตัวอย่างผลลัพธ์

```
============================================================
 ผลการทดสอบ: ผ่าน 59 รายการ · ไม่ผ่าน 0 รายการ
============================================================
```

ตรวจความพร้อมของระบบก่อนเปิดใช้งานจริงด้วย

```bash
npm run check
```

## 10. มาตรการความปลอดภัย

- **ตรวจสอบสิทธิ์จากฝั่งเซิร์ฟเวอร์เท่านั้น** ทุกหน้า `/admin/*` และ API ที่ต้องใช้สิทธิ์จะถูกตรวจ session ก่อนเสมอ
- **รหัสผ่านเข้ารหัสด้วย bcrypt** ไม่มีการเก็บรหัสผ่านแบบข้อความธรรมดา และไม่มีการฝังรหัสผ่านไว้ในหน้าเว็บ
- **ป้องกัน CSRF** ด้วยโทเคนแบบ Synchronizer Token ที่ผูกกับ session และมี retry อัตโนมัติเมื่อโทเคนเปลี่ยน
- **SQL Injection** — ทุกคำสั่ง SQL ใช้ prepared statement พร้อมพารามิเตอร์ ไม่ต่อสตริงจากข้อมูลผู้ใช้
- **XSS** — เทมเพลต escape ค่าที่แสดงทั้งหมด และตรวจสอบความปลอดภัยของลิงก์ที่ผู้ใช้กรอก (อนุญาตเฉพาะ http/https)
- **Session Hijacking / Fixation** — สร้าง session ใหม่ทุกครั้งที่เข้าสู่ระบบ เก็บ session ในฐานข้อมูล และตั้งค่าคุกกี้เป็น HttpOnly + SameSite=Lax
- **การอัปโหลดไฟล์** — ตรวจชนิดไฟล์จากเนื้อหาไฟล์จริง (ไม่เชื่อนามสกุลหรือค่า MIME ที่ผู้ใช้ส่งมา) จำกัดขนาด ตั้งชื่อไฟล์ใหม่ด้วยชื่อสุ่ม
  และโฟลเดอร์อัปโหลดถูกตั้งค่าไม่ให้รันสคริปต์ พร้อม `Content-Disposition` ที่ปลอดภัย
- **การเดารหัสผ่าน** — จำกัดจำนวนครั้งที่เข้าสู่ระบบผิดจากไอพีเดียว และจำกัดอัตราคำขอที่เขียนข้อมูล (rate limit)
- **Audit Log** — บันทึกทุกการกระทำสำคัญพร้อมผู้ใช้ ไอพี และเวลา
- **ความปลอดภัยของส่วนหัว HTTP** — ใช้ Helmet กำหนด Content-Security-Policy, X-Frame-Options และส่วนหัวความปลอดภัยอื่น ๆ
- **การป้องกันการเข้าถึงไฟล์** — เส้นทางแบบลำดับชั้น (`..`) และไฟล์ที่ไม่อยู่ในรายการที่อนุญาตถูกปฏิเสธ
- **หน้าหลังบ้านไม่ถูกจัดทำดัชนี** — `robots.txt` สั่งห้าม `/admin` และหน้า Admin ส่ง `<meta name="robots" content="noindex">`

## 11. การนำขึ้นใช้งานจริง (Production)

1. **ตั้งค่า `.env`**
   - `NODE_ENV=production`
   - `SITE_URL=https://your-domain.com`
   - `SESSION_SECRET` เป็นข้อความสุ่มยาวอย่างน้อย 32 ตัวอักษร
   - `COOKIE_SECURE=true` (เมื่อใช้งานผ่าน HTTPS)
   - สร้างผู้ใช้ฐานข้อมูลเฉพาะของเว็บไซต์ ไม่ใช้ `root`
2. **สำรองข้อมูล** ฐานข้อมูลและโฟลเดอร์ `backend/uploads`
3. **รันเซิร์ฟเวอร์เบื้องหลัง** ด้วย process manager เช่น PM2 หรือ systemd

   ```bash
   npm install -g pm2
   pm2 start backend/server.js --name project-hub
   pm2 save && pm2 startup
   ```

4. **วาง Reverse Proxy** (Nginx / Caddy) เพื่อทำ HTTPS และส่งต่อคำขอมาที่พอร์ต 3000
   พร้อมกำหนด `client_max_body_size` ให้สอดคล้องกับ `MAX_VIDEO_MB`
5. **ทดสอบหลังติดตั้ง** ด้วย `bash tools/smoke-test.sh https://your-domain.com` และ `npm run check`
6. เปลี่ยนรหัสผ่านผู้ดูแลเริ่มต้นทันที และตรวจประวัติการจัดการในหน้าตั้งค่า

> ระบบนี้เป็นเว็บแอป Node.js แบบ stateful (ใช้ session ในฐานข้อมูล) จึงควรรันเป็นโปรเซสเดียว หรือใช้ตัวจัดการ session ร่วมกันหากต้องการสเกลหลายอินสแตนซ์

## 12. การปรับแต่งและข้อจำกัด

### ปรับแต่งได้จากหน้าตั้งค่า (ไม่ต้องแก้โค้ด)

ชื่อเว็บไซต์ คำโปรย โลโก้ Favicon สี Accent ข้อความและปุ่มในส่วนแนะนำ ข้อมูลช่องทางติดต่อ ข้อความหน้าเกี่ยวกับเรา
จำนวนรายการที่แสดงบนหน้าแรก ข้อความ SEO และข้อความส่วนท้ายเว็บไซต์

### ปรับแต่งจากโค้ด

| ต้องการเปลี่ยน | แก้ที่ |
| --- | --- |
| ชุดสี ระยะห่าง และฟอนต์ของเว็บไซต์ | `frontend/assets/css/style.css` (ตัวแปรใน `:root`) |
| ชุดสีของระบบหลังบ้าน | `frontend/assets/css/admin.css` |
| ป้ายชื่อประเภทและสถานะ (ภาษาไทย) | `backend/config/constants.js` และ `frontend/assets/js/admin-core.js` |
| รูปแบบการ์ดและเลย์เอาต์หน้าเว็บ | `frontend/partials/*.ejs` และ `frontend/*.ejs` |
| ข้อความต้อนรับหน้าแรก | หน้าตั้งค่า → ส่วนแนะนำ (Hero) |

### ข้อจำกัดที่ทราบ

- ระบบออกแบบมาสำหรับ **ผู้ดูแลกลุ่มเล็กของค่าย** และใช้ session ฝั่งเซิร์ฟเวอร์ จึงยังไม่มีระบบสมาชิกสาธารณะ การสมัครใช้งาน หรือการแบ่งสิทธิ์ละเอียดกว่าระดับ `admin` / `editor`
- ไม่มีระบบแก้ไขเนื้อหาแบบ Rich Text Editor ในตัว (ใช้ข้อความล้วนโดยเว้นบรรทัดว่างเพื่อขึ้นย่อหน้า) เพื่อลดความเสี่ยงด้านความปลอดภัย
- การอัปโหลดวิดีโอเก็บเป็นไฟล์ในเซิร์ฟเวอร์ และกำหนดขนาดสูงสุดไว้ที่ 80 MB ต่อไฟล์ (ปรับได้ที่ `MAX_VIDEO_MB`) หากต้องการไฟล์ขนาดใหญ่ควรเปลี่ยนไปใช้บริการเก็บไฟล์ภายนอก
- สถานะกิจกรรมที่คำนวณอัตโนมัติจะอัปเดตเมื่อมีการเรียกดูหน้าหรือกด "ตรวจสอบกำหนดการ" ในระบบหลังบ้าน
  (หากต้องการให้อัปเดตตามเวลาจริงแม้ไม่มีผู้เข้าชม ควรตั้งงานด้วย `cron` ให้รัน `POST /api/events/sync` เป็นระยะ)

## 13. แก้ปัญหาการเชื่อมต่อฐานข้อมูล

หากพบข้อความ `Error: connect ECONNREFUSED 127.0.0.1:3306` ให้เปิดบริการ MySQL/MariaDB ก่อน แล้วตรวจสอบพอร์ตและค่าฐานข้อมูลในไฟล์ `.env`:

```powershell
Test-NetConnection 127.0.0.1 -Port 3306
npm run check
npm run migrate
npm start
```

บน Windows สามารถเปิด `services.msc` แล้วกด Start บริการ `MySQL80` หรือ `MariaDB` ได้ หากใช้ XAMPP ให้กด Start ที่แถว MySQL ใน XAMPP Control Panel

ดูขั้นตอนละเอียด รวมถึงกรณีใช้พอร์ตอื่นและข้อความผิดพลาด `ER_ACCESS_DENIED_ERROR` / `ER_BAD_DB_ERROR` ได้ที่ [TROUBLESHOOTING.md](TROUBLESHOOTING.md)
